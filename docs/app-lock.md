# アプリのロック

設定の「ロック」で、アプリを開くときに本人を確かめる(#100 の前半。保存するデータの暗号化は別の PR)。

| 設定 | 中身 |
| --- | --- |
| アプリのロック | 指紋・顔、または端末の画面ロック(PIN・パターン・パスワード)で確かめる(`androidx.biometric`、`BIOMETRIC_WEAK or DEVICE_CREDENTIAL`)。オンにする前に一度確かめる(確かめられない端末で締め出されないように) |
| ロックするまでの時間 | アプリを離れてから、すぐに・30 秒後・1 分後・5 分後・15 分後 |
| 最近使ったアプリで内容を隠す | すべての画面に `FLAG_SECURE` を付ける。アプリの一覧に内容が出ず、スクリーンショットも撮れない。ロックとは別に選べる |

## 仕組み

- `ui/lock/AppLockManager`: ただ1つの持ち主。`Application.ActivityLifecycleCallbacks` で、アプリのすべての Activity の出入りを見る。
  入り口(ランチャー・ディープリンク・ショートカット・共有・引用・クイック設定タイル・ウィジェット・通知)ごとに守りを足す必要がない。
  `FLAG_SECURE` もここですべての Activity の窓に付ける
- `domain/lock/AppLockStateMachine`: いつロックするかの純粋な処理(単体テストあり)
  - プロセスが始まったときは、ロックがオンならロックする(状態はプロセスの中だけに持つ)
  - アプリの画面が1つも見えなくなってから、決めた時間以上たって戻るとロックする(時刻は端末の起動からの経過時間。時計を戻してもごまかせない)
  - 回転などで作り直すとき、アプリの中で別の画面に移るとき、本人を確かめている間(端末の PIN の画面に移る)は、離れたことにしない
  - アプリの中でオンにしたときは、使っている途中なのでロックしない
- `ui/lock/AppLockGate`: すべての Activity の `setContent` の中(テーマの内側)に置く
  - ロックを解くまでは中身を組まない(ViewModel を作らず、データを読まない)
  - 解いたあとにまたロックしたときは、中身を残したまま不透明なロックの画面を重ねる(ファイルの選択などから戻った結果を受け取れるように)。
    下の中身は読み上げの対象から外し、触れず、入力中のキーボードは閉じる。戻るボタンではアプリを離れる
- ウィジェット: ロックがオンの間は、ブックマークのタイトルと処理の件数を出さない(押すとアプリを開き、そこで確かめる)
- 端末の画面ロックも生体認証も無くなったとき: 確かめられないので、「アプリのロックをオフにして開く」を出す
  (画面ロックを外せるのは、それを知っている人だけのため)
- 「全データを削除」で設定を初期化しても、オンにしたロックと「内容を隠す」は残す。バックアップには含めない(端末の設定)

## 守れないもの

- 通知の本文(再発見の通知など)はロックと関係なく出る。端末の設定で、ロック画面に通知の内容を出さないようにできる
- ロックしていない間に開いた別のアプリ(ブラウザ・PDF のビューアなど)に渡した内容
