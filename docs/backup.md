# バックアップと復元

設定の「データ」から、バックアップを書き出し・読み込みできる。

| 操作 | ファイル | 中身 |
| --- | --- | --- |
| バックアップを書き出す | `echomark-backup-日付.json` | DB のテーブル(下の表)とチャットのテンプレート |
| ファイルも含めて書き出す | `echomark-backup-日付.zip` | 上の JSON(`backup.json`)と、添付ファイル・オフラインコピーの本体(`attachments/…`) |
| バックアップを読み込む | どちらでも | 今のデータに**統合**する(置き換えない)。同じ URL のブックマークなどはスキップする |

形式の版は `BackupJson.CURRENT_VERSION`(今は 20)。古い版のファイルもそのまま読み込める(版の履歴は `BackupJson` の KDoc)。

## 何を含め、何を含めないか

一覧の正本は `app/src/main/java/.../data/backup/BackupCoverage.kt`。DB のすべてのテーブル・列と DataStore のすべてのキーについて、
含めるか、含めない理由を書いてある。`BackupCoverageTest` が、DB のスキーマ JSON(`app/schemas/.../<版>.json`)と
DataStore のキー(ソース)をこの一覧と比べ、載っていないものがあれば失敗する。

| もの | 扱い |
| --- | --- |
| ブックマーク・タグ・紐付け・会話・メッセージ・タグの別名・外したタグ・カテゴリ・スマートフォルダ・購読・ノート・コレクション・復習のカード | 含める |
| 要約の履歴(`summary_history`) | 含める(v20〜)。読み込んで追加したブックマークにだけ付ける |
| オフラインコピーの記録(`snapshotPath` など) | 含める(v20〜)。ファイルが読み込む端末に無ければ(zip に入っていなければ)外す |
| リンク切れの確認 | 「確認しない」を選んだものだけ。確認の状態は端末の中のもの |
| 処理の段・日時・失敗の理由、購読の確認の状態 | 含めない(端末の中の一時的な状態) |
| クラウド API の使用量(`api_usage`) | 含めない(別の端末で重ねて数えてしまう) |
| チャットのテンプレート(DataStore) | 含める(v20〜)。同じ名前・本文のものは足さない |
| 検索の履歴・「両方残す」と答えた重複・通知の記録・設定 | 含めない(端末の中のもの・端末の設定) |
| API キー | 含めない(秘密の情報) |
| 埋め込み(ObjectBox) | 含めない(読み込んだあとに作り直す) |
| 端末内モデル | 含めない(大きく、取り込み直せる) |
| 添付ファイル・オフラインコピーの本体 | zip のときだけ含める |

## 読み込みの安全

読み込みは、全体を確かめてから書き込む(`DataManagementRepositoryImpl.importBackup`)。

1. ファイルを読む。zip なら、キャッシュの一時的な場所に展開する(`BackupArchive.extract`)。
   名前が決まった形でないもの(`../` を含むものなど)・同じ名前の重なり・大きすぎるもの・空き容量を超えるものがあれば、断る。
2. JSON を読み、中身がそろっているかを確かめる(`BackupValidation`)。読めない要素・重なった ID・ファイルに無いものへの参照
   (DB で外部キーのあるもの)があれば、**何も書き込まずに**断る(読める分だけ取り込むと、気づかないところでデータが欠けるため)。
3. 添付ファイル・オフラインコピーを置き場所に入れる → チャットのテンプレートを足す → DB に統合する(1つのトランザクション)。
   どこかで失敗したら、入れたファイルを消し、テンプレートを元に戻す。DB はトランザクションで元のまま。
4. 一時的な場所を消す。

## テーブル・列・キーを足すとき

1. バックアップに入れるなら、`BackupData`・`BackupJson`(書き出しと読み込み)・`BackupDao`(`snapshot` と `merge`)に足し、
   `BackupJson.CURRENT_VERSION` を上げて、KDoc の版の履歴に書く。古い版を読むときの値も決める。
   外部キーのある参照なら `BackupValidation` にも足す。
2. 入れないなら、理由を決める。
3. どちらでも `BackupCoverage` に足す(`BackupCoverageTest` が通るまで)。入れる列は、`BackupCoverageTest` のすべての列に値を入れた
   データにも値を入れる(JSON に書き出されているかを確かめるため)。
4. 「全データを削除」で消えるかも決める(`BackupDao.deleteAll`・`DataManagementRepositoryImpl.deleteAllData`)。
