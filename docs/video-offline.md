# 動画のオフライン保存

動画のブックマークを、通信できなくても見られるように端末へ保存する。
**動画のファイルそのものは、ダウンロードが認められているものだけを保存する。** それ以外の動画(YouTube など)は、
映像・音声を保存せず、字幕・要約・サムネイルを保存する。

## 保存するもの

| 動画の種類 | 保存するもの | 根拠 |
| --- | --- | --- |
| YouTube | 字幕(取れたとき)・要約・サムネイル。**映像・音声は保存しない** | 下の「YouTube」 |
| PeerTube | 字幕(公開の API から)・要約・サムネイル。投稿者がダウンロードを許した動画は**動画のファイル**も(720p まで) | 下の「PeerTube」 |
| 動画のファイルへの直接のリンク(mp4・webm など) | **動画のファイル** | 下の「直接のリンク」 |
| そのほかの動画サイト(Vimeo・ニコニコ動画・TikTok・Twitch・Dailymotion) | 説明文(ページから取れたもの)・要約・サムネイル。字幕は取らない | 認められた字幕の取り方を確かめられていない |

字幕と要約は、ブックマークの本文(`bookmarks.content` の「字幕:」以下)と要約(`bookmarks.summary`)に入る。
DB の中にあるので、もともと通信せずに読める。オフライン保存の作業では、本文に字幕が無ければリンク先を取り直して入れ、
要約が無い・字幕を新しく入れたときは要約だけを作り直す(手で直した要約は置き換えない)。
サムネイルは端末に保存する(`offline_videos.thumbnailPath`)。

## サイトごとの判断

調べたのは 2026-11-20。規約は変わるので、サイトを足すとき・見直すときは、その時点の規約と API の説明を読み直す。

### YouTube

- [利用規約](https://www.youtube.com/t/terms)は、サービスが明示的に認めた場合か、YouTube と権利者の書面の許可がある場合を除き、
  コンテンツへのアクセス・複製・**ダウンロード**などを禁じている。映像・音声のストリームはダウンロードしない
  (player API の応答に入っている `streamingData` などの配信の URL は使わない)。
- 字幕: [YouTube Data API の captions.download](https://developers.google.com/youtube/v3/docs/captions/download) は
  「動画を編集する権限」が要り(OAuth)、他人の動画の字幕を取る公式の手段は無い。
  アプリは以前から、YouTube のアプリが視聴者に見せる字幕を、部品の `YouTubeTranscriptFetcher`(InnerTube の player API を
  Android のアプリとして呼ぶ)で取っている。公開された API ではなく、規約の上では「明示的に認められた方法」と言い切れない。
  **この PR では取り方を変えていない**(新しい取り方を足していない)。取り方を続けるかは利用者・開発者の判断に残す。
- サムネイル: ページの OG 画像(`i.ytimg.com`)を、ブックマークの一覧・詳細に出すのと同じ画像として1枚保存する。

### PeerTube

- 動画の情報(`GET /api/v1/videos/{id}`)と字幕(`GET /api/v1/videos/{id}/captions`、ファイルは `fileUrl`。古い版は `captionPath`)は、
  サーバーがだれにでも見せている公開の REST API([API の説明](https://docs.joinpeertube.org/api-rest-reference/api.html))。
  認証は要らない。
- 動画のファイルは、投稿者が動画ごとに「ダウンロードを許す」を選べる(`downloadEnabled`。
  [投稿の説明](https://docs.joinpeertube.org/use/create-upload-video))。ファイルを保存するのは、これが true のものだけ。
  落とすのは API が返す `fileDownloadUrl`(添付ファイルとして返すための URL。無ければ `fileUrl`)で、Web Video の `files` と
  HLS の `streamingPlaylists[].files` のうち、映像のある 720p 以下のいちばん高い画質(無ければいちばん低い画質)を選ぶ。
  ライブ配信は保存しない。
- サーバーごとにホストが違うため、動画ページのパスの形(`/w/<ID>`・`/videos/watch/<ID>`・`/videos/embed/<ID>`)で見分け、
  同じサーバーの API が PeerTube の答え(`uuid` と `name`)を返すかで確かめる(`PeerTubeUrls`・`PeerTubeFetcher`)。
  API を呼ぶ先は、ブックマークしたページと同じサーバーだけ。

### 直接のリンク

- パスが動画の拡張子(mp4・m4v・webm・mov・mkv・ogv)で終わるリンク、またはリンク先の種類が動画だったもの。
  リンクの先がファイルそのもので、開けばブラウザでもダウンロードされる。落とすときに Content-Type が動画(`video/…`。
  汎用の `application/octet-stream` なら拡張子)かを確かめ、動画でなければ保存しない。
- 100MB までのものは、これまでどおり本文の取得のときに添付ファイルとして保存している(そのブックマークは、詳細画面の
  プレビューからアプリの中で再生できる)。この欄は、それより大きいなどで添付ファイルにならなかったものが対象。

### 動画のファイルを保存しないサイト

- **Wikimedia Commons**: [再利用の説明](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia)は
  ファイルのダウンロードと利用を認めている(ファイルごとのライセンスの条件に従う)。ただし API の
  [User-Agent の方針](https://foundation.wikimedia.org/wiki/Policy:User-Agent_policy)が、連絡先(メール・Web サイト・
  ウィキの利用者)を User-Agent に入れることを求める。個人のアプリが利用者の連絡先を送るわけにはいかず、アプリとしての連絡先の
  決め方も決まっていないため、**入れない**(ファイルへの直接のリンク(upload.wikimedia.org の .webm など)は、上の「直接のリンク」として保存できる)。
- **Internet Archive**: 利用規約を読めていないため(2026-11-20 にページの本文を取得できなかった)、**入れない**。
  読めて、ダウンロードが認められていると確かめられたら足す。
- Vimeo(ダウンロードは投稿者が認めたものだけで、確かめるには認証が要る)・ニコニコ動画・TikTok・Twitch・Dailymotion
  (ダウンロードを認めた公開の手段を確かめられていない)。

## 動画のファイルの保存(ダウンロード)

- 詳細画面の「オフラインで見る」の「動画を保存」で始める。WorkManager の前景のワーク(`VideoFileDownloadWorker`)が、
  通知に進み具合を出しながら落とす。画面にも進み具合と「やめる」を出す。
- **Wi-Fi のときだけ**(既定はオン): 従量課金でない接続を条件にして積む。Wi-Fi から外れたら WorkManager が止め、
  つながったら途中のファイル(`offline_videos/<ブックマークの ID>.part`)の続きから Range で落とす(サーバーが続きを返さなければ始めから)。
- **上限**(既定 2GB。500MB〜10GB から選ぶ): 保存する動画の合計がこれを超えるものは落とさない(大きさが分かった時点・書きながら確かめる)。
- **空き容量**: 残りの分と余裕(200MB)が端末に無ければ落とさない。空き容量が少ないときは WorkManager も動かさない。
- 通信に失敗したら、何度か(続きから)試し直す。上限・空き容量・許されていない・動画でないときは、途中のファイルを消して止める。

## 再生

- アプリの中で再生する(`VideoPlayerActivity`。Media3 の ExoPlayer と PlayerView)。オフライン用に保存した動画と、
  添付ファイルの動画(詳細画面のプレビューを押す)を再生する。ほかのアプリで開く操作はそのまま残す。
- **通信しない**: 読むのは端末のファイルだけ(`FileDataSource`)。開けるのは、動画の置き場所と添付ファイルの置き場所の中のファイルだけ。
  HTTP で読む Media3 の部品は使わない(`NetworkPolicyCoverageTest` が確かめる)。
- 入れた部品: `androidx.media3:media3-exoplayer` と `media3-ui`(1.10.1)。APK の大きさの変化は PR に書く。

## 容量の管理

- 設定の「データ」→「オフラインの動画」: 使っている量と上限・端末の空き容量、Wi-Fi のときだけ・上限の設定、保存した動画の一覧
  (押すと再生・1件ずつ削除)、すべて削除。設定の「ストレージ使用量」にも「動画」として出す。
- 詳細画面からも、その動画だけを削除できる(字幕・要約・サムネイルは残る)。

## 保存先・削除・バックアップ

- 記録は `offline_videos` テーブル(v32。ブックマーク1件に1行)。ブックマークの削除を「元に戻す」で取り消せるよう外部キーにはせず、
  ブックマークが無くなった行は起動時の掃除(`UnusedAttachmentCleaner`)で消す。
- サムネイルは添付ファイルと同じ置き場所(`filesDir/attachments/`)に置く。参照されなくなったものは、ほかの添付ファイルと同じく
  猶予(1日)の後に消える。「すべてのデータを削除」で、記録・サムネイル・動いている保存の作業を消す。
- 動画のファイルは別の置き場所(`filesDir/offline_videos/`)に置く。参照されなくなったものは猶予(1日)の後に、
  途中まで落としたものはブックマークが無いか 7 日止まったままなら、起動時の掃除で消す。「すべてのデータを削除」でも消す。
- バックアップには入れない(`BackupCoverage` の `offline_videos`)。端末ごとの保存で、サムネイルはリンク先から取り直せ、
  動画は大きいため。アプリのバックアップ(zip)にも、Android のバックアップ(`backup_rules.xml`・`data_extraction_rules.xml`
  で `offline_videos/` を外している)にも入れない。ダウンロードの設定(Wi-Fi のときだけ・上限)も端末ごとの設定として入れない。
  字幕と要約はブックマークの本文・要約なので、バックアップに入る。

## 通信とオフラインモード

- 字幕・サムネイルの保存は WorkManager(`VideoOfflineWorker`)で行う。通信できるときだけ動く。小さいので、従量課金の接続でも動く。
- 動画のファイルは `VideoFileDownloadWorker`(上の「動画のファイルの保存」。既定は Wi-Fi のときだけ)。
- 通信はすべて共通の OkHttp の接続から作ったもの(`UrlContentFetcher`・`VideoFileDownloader`。ローカルネットワークに接続しない・
  オフラインモードで断る・リダイレクトで https から http へ落とさない)。
- オフラインモードの間は保存を始めず、画面で理由を出す。途中でオンにされたら、何も書かずに止める。
