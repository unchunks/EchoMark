# ポッドキャスト(ブックマークを音声で聞く)

選んだブックマーク(詳細画面の1件、または一覧の複数選択)から、話し言葉の台本を作り、端末の読み上げ(`TextToSpeech`)で音声にする。
台本は日本語で、1人の語り(`PodcastFormat.SOLO`)か、進行役と聞き役の2人の掛け合い(`PodcastFormat.DUO`)。

作るのは3つの段に分けて入れる。

| 段 | 中身 | 場所 |
| --- | --- | --- |
| 1. 台本と読みの整え | 台本を書く(AI・要約の読み上げ)、読み上げ用の整え、読みの辞書 | `domain/podcast/`・`data/podcast/`・`ui/podcast/ReadingDictionaryScreen.kt` |
| 2. 音声の生成と保存 | 端末の読み上げで音声ファイルにする、エピソードの保存と削除、作る画面・一覧 | `data/podcast/`(`PodcastGenerator`・`tts/`・`audio/`)・`worker/PodcastGenerationWorker.kt`・`ui/podcast/` |
| 3. 再生 | バックグラウンドの再生・通知・速さ・台本から聞く | `data/podcast/playback/`・`ui/podcast/PodcastPlayerScreen.kt` |

## 台本の作り方(`PodcastScriptWriter`)

1. 始まり・出典の紹介・終わりは決まった文(`PodcastTemplates`)。**出典は AI に任せず必ず入れる**
   (「2件目は、Zenn の記事「…」です。」・終わりに「出典は、…でした。」)。タイトルの後ろのサイト名(`… | Zenn`)は除く。
2. 1件ずつ、AI に紹介の台本を短い JSON で書かせる(`PodcastScriptPrompts.segmentPrompt`)。形が崩れたら1回作り直させ、
   それでも駄目ならその件は要約をそのまま読む。端末内 AI では、要約 500 文字・本文 500 文字までを渡す(プロンプト全体で 1,800 文字ほど)。
3. 1件ずつ、書いた台本(出典の紹介を含む)から、読み間違えやすい語の読みを AI に挙げさせる(`readingsPrompt`)。
4. AI を使えない(モデルが無い・キーが無い)とき・途中で AI が失敗したときは、残りを要約の読み上げにする
   (`ScriptGenerator.SUMMARY_READ`。端末内 AI の時間切れを何度も待たない)。

AI の実行場所は「チャット」の設定に従う(`AiTask.CHAT`。画面で結果を待つ生成なので、背景の解析より先に動く)。
ブックマークの中身は第三者の書いたものを含むので、中の指示に従わないよう伝える。

## 読み間違いを減らす工夫

読み上げの直前に、台本の各行を `SpeechNormalizer` で整える。台本の文(画面に出す文)はそのまま残し、整えた文だけを読み上げに渡す。
整えは何重にも重ね、先に決めた読みを後の整えで触らない(`SpeechPiece.Reading`)。

| 順 | 何をするか | 例 |
| --- | --- | --- |
| 1 | 読めないものを除く: コードブロック・URL・メールアドレス・HTML のタグ・Markdown の記号・引用番号・絵文字。全角・半角をそろえる(NFKC)。短いインラインのコードは記号だけ外す | `https://…` → (読まない) |
| 2 | 文の中の振り仮名を読みにする | `日本橋(にほんばし)` → にほんばし |
| 3 | **利用者の読みの辞書**(いちばん先に効く) | `EchoMark` → エコーマーク |
| 4 | **AI が台本から見つけた読み**(かなだけで、表記が台本に本当にあるものだけ) | `日本橋` → にほんばし |
| 5 | 電話番号・0 で始まる番号は1けたずつ読ませる(`SpeechPiece.Telephone`・`Digits`。読み上げに渡すときに `TtsSpan` の TELEPHONE・DIGITS を付ける: `SpeechSpans`) | `03-1234-5678` |
| 6 | 数の書き方: 日付・曜日・時刻・範囲・通貨・掛け算・版・マイナス | `2026/11/20(金)` → 2026年11月20日、金曜日 / `10:30` → 10時30分 / `10〜20` → 10から20 / `$100` → 100ドル / `v2.1` → バージョン2.1 |
| 7 | 数の後ろの単位 | `5km` → 5キロメートル / `8GB` → 8ギガバイト / `30℃` → 30度 |
| 8 | ドメイン名の点 | `example.com` → example ドット com |
| 9 | アプリに入れてある読み(`BuiltInReadings`: 単語として読む略語・製品名) | `NASA` → ナサ / `iPhone` → アイフォーン / `C++` → シープラスプラス |
| 10 | 残った大文字の略語は1文字ずつ読む(5文字以上で母音のあるものは単語として残す) | `NHK` → エヌエイチケー / `A社` → エー社 |
| 11 | 残った記号を、読む言葉・区切りにするか除く | `&` → アンド / `【速報】` → 速報、 / `→` → 、 |

AI の読みを台本の書き換えにしないのは、端末内の小さなモデルが読みを誤っても、内容(数字・名前)が変わらないようにするため。
AI には「読み上げで読めないもの(URL・コード・記号・絵文字・箇条書き)を書かない」ようにも伝えてある。

整えの決まりは `SpeechNormalizerTest` に、書き方ごとの例で確かめてある。

### 読みの辞書

`AppSettingsRepository.readingDictionary`(DataStore の `reading_dictionary`。JSON の配列)。画面は `ReadingDictionaryScreen`
(`Routes.READING_DICTIONARY`)。表記 40 文字・読み 80 文字・500 件まで。英字だけの表記は大文字・小文字を区別せず、
前後が英数字でないところだけで当てる(`AI` が `MAIL` の中で当たらない)。画面の「読みを確かめる」に文を入れると、
読み上げに渡す形(辞書・数字・記号を整えたもの)をその場で見られる。

バックアップに入れる(`BackupJson` v23 の `readingDictionary`)。読み込むときは今の辞書に足し、同じ表記は今の読みを残す。

## 音声の生成と保存

### 入口

- 詳細画面のメニュー「ポッドキャストにする」、一覧の複数選択の「その他の操作」→「ポッドキャストにする」(一覧に並んでいる順に紹介する)
  → 作る画面(`Routes.PODCAST_NEW`。話し方を選ぶ。1回に 10 件まで)
- エピソードの一覧(`Routes.PODCASTS`): 一覧のメニュー「ポッドキャスト」・できた通知(`echomark://podcasts`)から開く。読みの辞書はここの上のボタンから

### 作り方(`PodcastRepositoryImpl` → `PodcastGenerationWorker` → `PodcastEpisodeRunner` → `PodcastGenerator`)

1. 作り始めると、作成中のエピソードを保存し、WorkManager に積む(エピソードごとに1つ。端末内 AI と読み上げで数分かかるため、
   通知つきのフォアグラウンド。Android 15 からは mediaProcessing、それより前は dataSync)
2. 台本を書く(上の「台本の作り方」)→ 行ごとに読みを整える(利用者の辞書 → AI の読み)
3. 行ごとに端末の読み上げで WAV にし(1回に 1,000 文字まで)、1つの WAV につなぐ(`WavJoiner`。行の間に 0.35 秒、紹介の切り替わりに 0.8 秒の間)。
   声によって周波数・チャンネル数・ビット数が違っても、最初の音声の周波数のモノラル 16 ビットにそろえる(`WavAudio`)
4. 行ごとに、画面の文・読み上げに渡した文・音声の中の始まりの位置を残す(再生の画面で台本と音声を合わせるのに使う)
5. 作れなかったら、理由を付けて失敗として残す(読み上げのアプリが無い・日本語の端末内の声が無い・ブックマークが消えた など)。一覧から作り直せる

### 読み上げ(`AndroidPodcastSpeechEngine`)

- **端末の中だけで読む**: 日本語の声のうち、通信の要らない(端末に入っている)ものだけを使い、読み上げのたびに通信による合成を断る
  (`KEY_FEATURE_NETWORK_SYNTHESIS` を false)。台本(ブックマークの中身)を読み上げのアプリが端末の外に送らない。オフラインモードでも使える
- 2人の掛け合いでは、日本語の端末内の声が2つ以上あれば聞き役に別の声を、1つしか無ければ同じ声の高さを変える
- クラウドの読み上げは入れていない(`CLOUD_AI_ENABLED = false` で、クラウドの AI がどの用途でも選ばれないため)

### 保存と削除

- `filesDir/podcasts/<id>/episode.json`(台本・出典・使った読み・長さ)と `episode.wav`。DB には持たない(スキーマの変更なし)
- バックアップに入れない: アプリのバックアップ(JSON・zip)には入らず、`backup_rules.xml`・`data_extraction_rules.xml` で
  Android の自動バックアップと端末間の転送からも外す。音声は大きい(1 分で 3 MB ほど)ので、一覧から1件ずつ・30 日より前のもの・すべてを消せる
- 一覧の「使った読み」から読みを直すと、読みの辞書に入れる(次に作るときから使う)。「作り直す」で同じブックマーク・話し方で作り直せる
- 詳しい情報の「ほかのアプリで聞く」で、音楽のプレーヤーなどに渡せる(FileProvider の `podcasts/`)

## 再生

一覧の「聞く」で再生の画面(`Routes.PODCAST_PLAYER`)を開くと、再生を始める(もう再生していれば続ける)。
画面を離れても再生は続き、メディアの通知・ロック画面・イヤホンのボタンから操作できる。通知をタップすると再生の画面に戻る。

- **画面**: 出典(その紹介から聞く・元のブックマークを開く)、台本(読んでいる行を色で示し、見える位置に保つ。行をタップするとそこから聞く)、
  位置のつまみ・10 秒戻る・再生と一時停止・30 秒進む・速さ(0.75〜2 倍)。行の位置は、作るときに残した `EpisodeLine.startMs`(`EpisodeTimeline`)
- **仕組み**: Media3 の `MediaSessionService`(`PodcastPlaybackService`)と ExoPlayer。画面からは `MediaController` でつなぐ
  (`MediaControllerPodcastPlayback`。`PodcastPlayback` を通すので、テストでは Fake に差し替える)。部品は develop の Media3(1.10.1)に
  `media3-session` を足しただけ
- **通信しない**: 読むのはエピソードの置き場所の音声だけ(`FileDataSource`)。再生するものはエピソードの ID で受け取り、サービスがファイルを決める
  (できていないエピソード・置き場所の外のファイル・URL は再生しない)
- **つなげる相手を限る**: サービスは通知・ロック画面・Bluetooth から操作できるよう exported だが、つなげるのはこのアプリ・メディアの通知・
  端末(プラットフォームのセッションを通すもの)・車の画面だけ。ほかのアプリは、題名を読めず操作もできない
- **アプリのロック中は題名を出さない**: ロック・内容を隠す設定がオンなら、通知・ロック画面の題名は「ポッドキャスト」にする
- 話し声として再生する(ほかのアプリが音を出すと止まる・イヤホンを抜くと止まる)。エピソードを消すと、再生していれば止める
- 速さはアプリを開いている間は覚えておく(設定には残さない)。どこまで聞いたかも残さない(開き直すと最初から)
